# LIMITLESS · 스테이지별 시간과 보너스 휴식

## 문제와 요청

학습 단계가 길게 이어지는 모드에 TIME ATTACK 대신 LIMITLESS라는 이름을 사용하고, 전체 공통 60초가 아닌 매 스테이지별 시간을 제공해 달라는 사용자 요청이다. 초반 쉬운 단계는 15초, 이후는 60초이며 5단계마다 영상으로 잠깐 쉬도록 요청했다. 학습 효과가 입증되었다는 의미는 아니다.

## 변경과 이유

- 메뉴·시작 화면 이름을 LIMITLESS로 변경. 내부 timeAttack ID 및 기존 저장 기록은 호환성을 위해 유지했다.
- 1–3단계(2×2)는 매번 15초, 4단계 이후는 매번 60초. 클리어할 때 새 시간을 지급하며, 막힌 판을 같은 단계에서 다시 배치할 때는 시간을 추가하지 않는다.
- 5, 10, 15…단계 클리어 후 BONUS BREAK 카드와 기존 GREAT 축하 영상을 표시한다. 별도 상태로 게임 시계와 판 입력을 멈추고, 화면을 누르면 다음 단계의 새 시간으로 이어간다. 영상 중에도 건너뛸 수 있고 기존 종료 축하 화면의 터치 정책은 유지한다.
- 시간 초과의 Retry는 저장된 현재 단계부터 새 제한 시간으로 시작한다. 다음 단계로 건너뛰지 않는다. 점수는 기존처럼 재시작 시 새로 계산한다.
- 시작 안내도 현재 단계에 맞는 15/60초로 표시한다. 아이콘 박스 크기는 유지했다.

## 검증과 한계

- 단위 테스트 133개 및 프로덕션 빌드 통과. 단계 시간 초기화, 15→60초 경계, 동일 단계 재배치 시 시간 미지급, 보너스 상태 복귀를 포함한다.
- 모바일 브라우저에서 1단계 15초, 5단계 클리어→영상, 영상 중 6단계 시간 정지, 터치 후 타이머 재개 확인. 브라우저 예외 없음.
- 재현 스크립트 개발 중 신규 저장값 초기화 누락과 기존 축하 화면의 터치 제한을 발견해 수정한 뒤 최종 검증했다.
- 실제 기기의 음향, Safari 재생, 장시간 모든 단계의 연속 플레이는 이번 검증에 포함하지 않았다. 모든 5의 배수 경계는 동일한 조건식을 사용하며 화면 검증은 5→6을 대상으로 했다.
- [verification.json](verification.json)에 촬영 시각·브라우저 버전·원본 SHA-256을 보존했다. [check.mjs](check.mjs)는 게임 런타임에서 import하지 않는다. 확정 자료를 보존하기 위해 다음 캡처는 새 폴더에서 실행해야 한다.
