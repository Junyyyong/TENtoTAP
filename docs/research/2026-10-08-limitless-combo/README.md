# LIMITLESS 5콤보 보너스·선택 취소 시 초기화

## 문제와 사용자 결정

사용자는 LIMITLESS 본게임의 점수가 잘 오르지 않아 연속 정답 보상을 제안했다. 대화에서 **5번째 연속 정답부터 정답마다 +20점**, 보너스는 더 커지지 않으며 **선택 취소도 콤보 단절**로 확정했다. 현재 OH MY GOD의 점수 경계는 `src/ui/screens/cheer.ts`의 **1,400점 이상**으로 유지한다. 사용자 언급의 1,500점으로 변경하지 않았다.

## 무엇을 왜 바꿨는가

- LIMITLESS 튜토리얼 뒤 60초 본게임만 적용. 1~4연속은 기존 기본 점수(2/3/4/5블록 = 10/20/40/80점), 5연속부터 기본 점수+20. 6·7연속도 각각 +20으로 고정한다.
- 연속 횟수를 게임 상태의 `limitlessCombo`로 관리한다. UI에만 있는 카운터로 점수를 계산하지 않아 점수 팝업·SCORE·BEST·결과 점수가 같은 지급액을 사용한다.
- 고른 블록을 다시 눌러 한 개만 빼도 초기화. 보드 주변 빈 영역에서 선택 전체 취소, 진행 중 포인터 취소로 선택이 없어지는 경우도 초기화. 취소는 점수/시간 벌점이 아니다.
- 확정 오답은 콤보 초기화+기존 −1초. 정답 후 자동 선택 해제·판 교체와 일시정지/재개는 콤보를 끊지 않는다. 새 게임/재시도는 0에서 시작한다.
- 자동 정리와 명시적 취소를 구별하기 위해 BoardView에 별도 `onCancel` 이벤트를 사용한다. 단순 `onSelectionChange([])`를 취소로 해석하지 않는다.
- 기존 보드 아래 안내 한 줄을 콤보/보너스 표시로 사용한다. 기본 박스·폰트·색·크기·배치는 바꾸지 않았다. 점수 팝업은 기본+보너스의 실제 합계다.
- 튜토리얼·TIMELESS·ENDLESS·이전 내부 모드에는 보너스를 적용하지 않는다. 패키지/서명/저장 키·형식/기존 기록을 유지한다. 콤보 횟수는 실행 중 상태이며 저장 항목을 추가하지 않는다.

의도는 연속으로 정확하게 선택하는 플레이에 보상을 주는 것이다. 정상 플레이의 점수 분포·OH MY GOD 도달률·사용성 개선은 아직 사용자 실험으로 측정하지 않았다. 높은 점수가 더 쉬워질 것이라는 설계 기대와 검증된 산술을 구분한다.

- 보너스 포함 BEST 저장을 확인했고 다른 모드 최고기록·튜토리얼 진도는 보존했다. 저장 파일 자체는 수정하지 않았다.
