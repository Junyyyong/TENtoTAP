# 블록별 랜덤 색상

## 요청과 변경 이유

숫자별로 고정된 블록 색을 없애고 같은 숫자도 서로 다른 색이 될 수 있게 해 달라는 사용자 요청이다. 기존 아홉 색 팔레트는 유지하고 숫자와 무관하게 블록마다 독립적으로 추첨한다. 같은 색이 우연히 겹칠 수 있으며 모든 블록의 색이 달라야 하는 규칙은 아니다.

## 구현

화면 전용 BlockColors가 색 번호를 보존한다. 시계 갱신, 선택, 오답 및 힌트 렌더링에서는 배정된 색을 다시 추첨하지 않는다. 새 판, 교체된 숫자, 비었다가 다시 채워진 칸은 새 색을 배정한다. 기존 선택/오답 강조 효과는 유지하며 강조가 풀리면 배정 색으로 돌아온다. 선택 수식의 작은 숫자 칸도 해당 블록의 색을 사용한다.

게임 생성 난수와 분리한 crypto 난수를 사용하므로 색상 추첨은 정답·점수·제한 시간에 영향을 주지 않는다. 표시 색은 저장 진도에 기록하지 않으며 새 게임/판 재설정에는 다시 추첨한다. 판 구조가 재배치되는 경우 위치별 표시 색을 갱신할 수 있다. 다른 게임 저장소는 변경하지 않았다.

직전 미푸시 작업인 모드 설명 한 줄 및 기존 박스 높이 복원도 현재 화면에 포함된다. 이 부수적 차이는 색상 변경과 구분한다.

## 검증과 한계

- 테스트 136개와 프로덕션 빌드 통과. 동일 숫자에 다른 색 배정, 복제된 보드 렌더링에서 색 유지, 재생성 및 빈 칸 재충전의 색 갱신을 검증했다.
- 모바일 Chrome에서 시간 경과·선택 후 전체 배정 색 유지와 수식 색 일치를 확인했다. 브라우저 예외 없음.
- 모든 색 조합의 가독성 또는 학습 효과를 실증한 것은 아니다. 실기기 접근성·장시간 플레이 검증은 포함하지 않았다.
- [check.mjs](check.mjs)는 런타임에서 import하지 않는 연구용 스크립트다. 확정된 자료를 덮어쓰지 않도록 후속 촬영은 새 경로를 사용한다.
