# 산식 결과 확인 시간·튜토리얼 영상 다양화·영상 재생 보강

## 후속 요청: 새 NOT BAD 음원·영상

사용자가 푸시 전에 업로드한 커밋 `16d7856`의 `1. notbad.webm/.mp4/.mp3`를 배포용 6번 세트로 연결했다. 기존 업로드 및 연구 원본은 보존했다. VP9/HEVC 영상 모두 960×960, 약 6.04초다. 등급 기준과 튜토리얼에서 NOT BAD를 제외하는 정책은 바꾸지 않았다.

추가 재현은 `16d7856`을 임시 폴더에 추출한 구버전 영상과 새 작업 트리를 비교한다: [이전](before-zero-score-video.png), [교체 후](after-zero-score-video.png), [스크립트](check-notbad.mjs), [검증·PNG 해시](notbad-verification.json). 아래 본문 `13edebf` 기준 전후 촬영과는 별도 촬영이다.

새 배포 자산 SHA-256:

- MP3: `bbad27b43c2cfa3b90f35eab8adb5996ea45d41539d295f393a2c2d45a241272`
- HEVC: `e04468f793163cd51b08df0242e558c62d836175a12206f9197a0549152b57aa`
- WebM: `6502297798578783379285d018dd361337e82c0d43d43202b6ef89094a4e5c50`

## 요청과 문제

사용자는 SUM=? 자리에 정답/오답 모두 전체 산식과 계산 결과를 제시해 학습자가 확인할 시간을 요청했다. 별도 확인 버튼은 원하지 않는다고 명확히 했으며 1.5초 자동 진행, 입력·타이머 정지 방식에 동의했다. 또한 튜토리얼 완료 영상이 GREAT로만 반복되는 점을 바꾸고, 가끔 영상 없이 소리만 들리는 현상을 점검하도록 요청했다.

## 변경 내용과 이유

- 유효한 조합과 거절된 조합 모두 실제 합계를 1.5초 유지한다. 예: `9 + 1 = 10`, `9 + 3 = 12`. X 대신 계산 결과를 남긴다. 정답은 기존 초록 테두리와 CORRECT, 오답은 붉은 결과/테두리와 TRY AGAIN으로 구분한다. 제한된 블록 수가 틀리면 필요한 개수도 안내한다.
- 2~5개 전체 항과 블록별 색을 유지한다. 정답 블록 제거·점수·다음 단계는 확인 시간 뒤에 처리한다. 오답은 확인 후 다시 선택한다. 별도 버튼/탭 없이 자동 진행한다.
- 모든 게임 모드의 이 입력 경로에 적용한다. 확인 동안 시계·ENDLESS 블록 추가·게임 입력·아이템을 정지한다. 메뉴로 나가면 예약된 진행을 취소한다. 숨겨진 탭에서는 확인 화면을 넘기지 않는다. 플레이 점수 규칙은 유지하지만, 실제 경과시간에 비해 플레이 시계는 확인 시간만큼 더 짧아진다.
- 5·13·22·30단계 영상 시점은 그대로다. NOT BAD를 제외한 GOOD TRY/GREAT/AMAZING/UNBELIEVABLE/OH MY GOD 다섯 종류를 섞어 중복 없이 한 번씩 사용한 뒤 다시 섞는다. 연속 같은 영상도 피한다. 한 튜토리얼에는 네 기회뿐이므로 네 종류가 나오며, 남은 종류는 같은 앱 세션의 다음 플레이에 이어서 사용된다. 페이지 새로고침 시 순서는 다시 생성된다. 본게임 결과 등급은 여전히 점수 기준이다.
- 영상은 가능하면 실제 출력 프레임 콜백 뒤에 소리를 시작한다. 버퍼링/멈춤에는 소리를 정지하고 복귀 시 영상 시간에 맞춘다. 최초 재생 실패/프레임 지연에는 다른 형식(WebM↔HEVC)을 재시도한다. 둘 다 실패하면 소리만 남기지 않고 문구와 탭 이동 상태로 끝낸다. 이 대체 형식은 브라우저에 따라 투명도가 다를 수 있다.
- 이전 재생의 이벤트/프레임/타이머를 정리해 늦게 도착한 이벤트가 새 소리를 재생하지 않도록 했다. 오디오 권한 준비가 영상 재생 중 사운드 소스를 바꾸지 않도록 방지했다.

소리만 나온 사용자 환경은 재현되지 않았으므로 원인을 렉으로 단정하지 않는다. 기존 코드는 `playing` 이벤트 이후 영상 버퍼링에 대한 사운드 정지가 없었고, 해당 취약 경로를 보강했다.

## 검증 및 한계

- 촬영일 2026-09-20. Chrome 152 계열, 390×844 CSS px / DPR 2, **780×1688 PNG**. 새 프로필·동일 제어 시계·숫자 난수 초기값. 블록 색 crypto 난수와 실제 영상 프레임은 다를 수 있다. 과거 의존성 전체 대신 현재 Vite를 사용했다.
- 변경 전 1~5단계, 변경 후 1~30단계를 실제 입력으로 풀었다. 저장 진도나 가짜 화면을 주입하지 않았다. 비교 사진은 같은 종류의 입력 직후이며, 이전 화면은 즉시 다음 단계로 넘어가는 차이가 있다.
- 확인 중 합계 유지, 타이머/단계 유지, 자동 다음 단계, 네 종류의 서로 다른 영상 디코딩·재생 시간 증가, 30단계 후 60초 본게임 안내를 확인했다. 페이지 JS 오류 없음.
- 단위 테스트 178개 및 프로덕션 빌드 통과. 프레임 전 소리 차단, 버퍼링 시 정지·재동기화, 두 형식 실패 시 무음 종료, 늦은 프레임 취소, 영상 분배를 단위 테스트로 검증했다.
- 과거 임시 서버에서는 Vite 허용 경로 문제로 배경음악 파일 요청이 거절되었다. 산식/영상 비교 화면 재현에는 영향이 없었으나 이번 전후 촬영을 과거 BGM 검증 근거로 쓰지 않는다.
- 실제 실패/대체 형식은 단위 테스트의 모의 미디어로 검증했다. 실제 Chrome 검증은 기본 WebM 재생이며, Safari HEVC와 사용자 기기의 원래 현상은 미검증이다. PNG만으로 음향 동기화나 학습 효과를 입증할 수 없다.
- [재현 스크립트](check.mjs), [촬영 조건·검증 결과·PNG SHA-256](verification.json). 재촬영은 새 출력 폴더를 사용해 확정 원본을 보존한다. 스크립트는 게임에 import하지 않는다.
