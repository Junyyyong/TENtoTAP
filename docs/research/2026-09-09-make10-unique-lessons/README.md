# MAKE10 · 유일 정답 튜토리얼

## 문제 / 사용자 요청

초반부터 판 전체를 비우게 하는 대신, 정답 한 조합을 찾으면 한 스테이지가 끝나도록 요청했다. 이름도 LIMITLESS에서 MAKE10으로 변경한다. 2×2에서는 두 숫자, 3×3에서는 세·네·다섯 숫자 조합을 각각 한 번 이상 연습한 범위를 튜토리얼로 정의한다.

## 무엇을 왜 변경했는가

- 1–5단계는 사용자가 제시한 네 숫자 예시를 그대로 사용한다. 정답 두 숫자를 맞추면 방해 숫자가 남아도 다음 단계로 진행한다.
- 6단계는 3+1+6, 7단계는 2+2+2+4, 8단계는 2+2+2+2+2가 유일한 정답이다. 반복된 숫자도 각각 별개 버튼으로 세어 모든 부분집합을 검사했다. 원문의 방해 숫자 6은 답의 6과 중복되므로 그대로 사용하지 않았다.
- 3×3 판을 아홉 버튼으로 채우면서 다른 정답을 만들지 않도록 방해 숫자는 반복될 수 있다. 특히 세 숫자 판의 방해 숫자는 5와 여러 8이다.
- 정답으로 선택한 숫자에 대해서만 점수를 부여한다. 방해 숫자는 추가 점수가 아니다.
- 1–5단계는 각 15초, 이후 각 60초. 5단계마다 보너스 영상과 시계 정지 정책을 유지한다.
- 9단계부터 전체 판 비우기 규칙으로 돌아가고, 3×3부터 크기별 12단계를 진행한다. 81단계부터 9×9다.
- 저장 ID와 기존 진행 단계는 보존한다. 기존 사용자의 진도를 초기화하지 않으므로 이미 8단계를 넘긴 사용자는 새 튜토리얼을 자동으로 다시 하지 않는다.

## 검증

- 단위 테스트 134개와 프로덕션 빌드 통과. 모든 초반 판의 부분집합 전수 검사로 버튼 기준 정답이 딱 하나이며 의도한 개수인지 확인했다.
- 단계별 단일 정답 후 진행·정답만 점수 지급·시간 재설정·9단계 전체 비우기 복귀·장기 판 생성·시간 초과·입력 잠금·동일 단계 재배치 시간을 검사했다.
- 모바일 Chrome에서 1→9단계를 실제 터치로 진행하며 5단계 보너스도 확인했다. 실기기 Safari와 장시간 사용성/학습 효과는 검증하지 않았다.
- [verification.json](verification.json): 촬영 시각, 브라우저 버전, 조건, PNG SHA-256. [check.mjs](check.mjs)는 연구용이며 게임에서 import하지 않는다. 확정 자료를 보존하려면 다음 촬영은 새 폴더에 저장한다.
