# 단계 시작 전 큰 안내

## 요청 / 문제

사용자는 판 아래의 블록 개수·전체 비우기 안내가 작아 잘 보이지 않는다고 지적했다. 작은 상시 안내를 없애고, 지정 단계 시작 전에 반투명 검은 배경과 큰 글씨로 표시한 뒤 탭해야 시작하도록 요청했다.

## 변경 내용

| 시작 단계 | 큰 안내 |
|---|---|
| 1 | MAKE 10 |
| 6 | USE 3 BLOCKS TO MAKE 10 |
| 14 | USE 4 BLOCKS TO MAKE 10 |
| 23 | USE 5 BLOCKS TO MAKE 10 |
| 30 | CLEAR ALL BLOCKS |

검은 배경 불투명도 74%, 기존 서체의 큰 흰 글씨와 Tap to start를 표시한다. 화면 전체가 시작 버튼이므로 탭 또는 키보드 Enter/Space로 진행한다. 모바일에서는 긴 안내를 두 줄로 나눈다.

별도 lessonIntro 상태에서 시계와 판 입력을 정지한다. 안내 중 정답 반짝임은 숨기고 탭 후 다시 표시한다. 시작 탭은 판 선택으로 전달되지 않는다. 해당 단계에서 Retry/이어하기로 새 게임을 시작해도 안내를 보여준다. 다른 단계에는 추가 탭을 요구하지 않는다.

6·14·23단계는 이전 단계의 보너스 영상 → 안내 → 탭 → 게임 순서다. 30단계는 29단계 완료 직후 안내를 보여주며 영상은 30단계 완료 뒤에 나온다. 기존 영상 일정·숫자·정답·색·제한 시간은 유지한다.

판 아래의 평상시 작은 목표 안내를 제거했다. 오답 피드백과 NEXT BOARD 상태 표시는 그대로다. 모드 이름 LIMITLESS와 게임 상단 MAKE 10은 변경하지 않았다.

## 검증과 한계

- 테스트 142개 및 프로덕션 빌드 통과. 다섯 안내 단계와 상태 전환을 단위 테스트했다.
- 모바일 Chrome에서 1→31 실제 터치 진행. 다섯 안내의 표시, 안내 중 시간 정지·반짝임 없음, 시작 탭의 선택 누출 없음, 탭 후 안내 제거·기존 반짝임, 보너스 순서와 30단계 전체 클리어를 검사했다.
- 브라우저 검증에서 초기 숨김 스타일 우선순위 문제를 발견해 `.lesson-intro.hidden`으로 수정한 뒤 재검증했다.
- 29단계 완료 터치가 새 안내의 클릭으로 이어지는 경우를 발견해, 안내가 열린 뒤 새 pointerdown이 있어야 터치로 시작되도록 수정했다. 키보드 활성화는 별도로 허용한다.
- 학습 효과·실기기 Safari·스크린리더 사용성까지 검증한 것은 아니다. [check.mjs](check.mjs)는 게임에서 import하지 않는 연구용 스크립트이며 다음 촬영은 새 폴더에 저장한다.
