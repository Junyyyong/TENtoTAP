# 출시 전 업데이트에 대비한 저장 안정화

## 문제/요청

사용자는 업데이트할 때 기록·스테이지가 사라지는 것 같다고 보고했고, 앱 삭제·데이터 삭제·휴대전화 교체 복구는 제외한 **일반 앱 업데이트 시 기록 유지**를 요청했다. 기존 버전은 앱에서도 브라우저 localStorage만 사용하며 저장 실패를 조용히 무시했다.

이번 재현에서는 이전 커밋도 같은 주소·브라우저 저장소에서 새로고침하면 진도가 유지되었다. 따라서 사용자에게 발생했던 초기화의 원인을 확정하거나, 업데이트가 기존 데이터를 삭제했다는 실험 결과로 해석하지 않는다. 접속 출처/프로필 변경과 과거 테스트 설정 등은 가능한 원인일 뿐 확정된 원인이 아니다.

## 무엇을 왜 바꿨는가

- Android 앱에서는 공식 `@capacitor/preferences` 8.0.1의 SharedPreferences를 사용한다. 웹은 기존 localStorage를 사용한다. 앱 ID와 기존 저장 키 `makezero.*.v1`은 변경하지 않았다.
- 앱 시작 전 모든 저장값을 비동기로 읽은 다음 게임을 만든다. 읽기 실패를 신규 설치로 오인하여 초기값을 덮어쓰지 않고 재시도 화면을 표시한다.
- 네이티브 기록이 없을 때만 해당 앱 WebView의 기존 localStorage 기록을 이전한다. 기존 원본은 삭제하지 않으며, 이전이 끝난 뒤에는 네이티브 기록이 우선이다. 외부 브라우저의 웹 기록을 새 앱으로 자동 이전하는 기능은 아니다.
- 저장은 게임 진행/점수/설정 변경 때 즉시 요청한다. 비동기 쓰기는 순서대로 처리하고 최신 값을 유지한다. 화면 전환·복귀 시에도 미완료 저장을 재시도한다.
- 저장 실패는 안내하고 메모리에 최신 미완료 값을 유지한다. Retry 성공 시 안내가 사라진다. 실패 안내가 남은 상태에서 프로세스가 종료되면 미완료 변경분은 손실될 수 있다. 운영체제의 갑작스러운 종료나 디스크 장애까지 무조건 보장하는 기능은 아니다.
- 네이티브 저장에는 직전 정상값 백업을 두어 원본 누락/잘못된 JSON에서 복구한다. 두 사본 모두 읽을 수 없으면 초기화하지 않고 시작을 막는다. 복구가 필요했던 경우 최신 변경분 일부는 이전 정상값으로 돌아갈 수 있다.
- 저장 형식은 출시 버전과 분리한다. 기존 필드에 없는 값만 기본값으로 채우며, 현재 코드가 모르는 추가 필드도 저장 때 보존한다.

LIMITLESS는 기존대로 **튜토리얼 단계 단위** 이어하기이며 판의 숫자·부분 선택·남은 시간까지 복원하지 않는다. ENDLESS/TIMELESS의 진행 중 한 판 복원은 추가하지 않았고 최고기록·설정은 보존한다. 오늘 기록만 날짜 변경 시 초기화한다. 점수·시간·오답 벌점·영상 규칙은 변경하지 않았다.

설계 참고: [Capacitor Preferences 공식 안내](https://capacitorjs.com/docs/apis/preferences). 로그인·서버 동기화·기기 변경 복구는 이번 범위에 없다.

## 결과와 한계

- 단위 테스트 **202개 통과**(기존 178 + 저장 관련 24). 기록·설정 이전, 31 완료 표식, 알 수 없는 추가 필드, 쓰기 순서, 실패 후 재시도, 백업 복구, 오래된 필드 기본값, 오늘 기록만 갱신하는 동작을 검사했다.
- `npm run build` 통과. `npx cap sync android`에서 Preferences 플러그인 연결 확인.
- 브라우저 시나리오: 세 모드 기록 유지, 실제 선택으로 10→11 저장, 새 실행 환경에서 11단계 복원, 쓰기/읽기 실패 안내 및 재시도, 웹판 재로딩 확인. JavaScript pageerror 없음.
- 네이티브 경로 검증은 실제 Capacitor JS 플러그인에 **Node Map 기반 테스트 브리지**를 연결한 것이다. Android SharedPreferences의 실제 디스크 동작이나 APK 설치 업데이트를 검증한 것이 아니다.
- 현재 환경에 Java 런타임·Android SDK/연결 기기가 없어 Android 빌드 및 실기기 업데이트 검증은 하지 못했다. AAB 생성·Play Console 업로드·배포는 하지 않았다.
- 이전 소스 실행은 현재 설치된 의존성을 사용했으며 당시 의존성 전체를 복원한 것은 아니다. 기존 연구 자료는 변경하지 않았다.

출시 전 별도 실기기 확인: 같은 applicationId와 호환되는 서명으로 구버전 설치 → 튜토리얼/세 모드 기록/음악 설정 변경 → 앱 삭제 없이 versionCode가 높은 새 버전 설치 → 진도·기록·설정 확인. Play 테스트 트랙에서도 같은 순서로 확인한다. Preferences 그룹/저장 키는 임의 변경하지 않는다.

[재현 스크립트](check.mjs), [검증 결과·브라우저 버전·소스/PNG SHA-256](verification.json). 재촬영은 새 `CAPTURE_OUT`을 지정한다. 브라우저 자동화 라이브러리는 `PLAYWRIGHT_MODULE`, Chrome은 `CHROME_PATH`로 별도 지정할 수 있다. 이 스크립트는 게임 런타임에 import하지 않는다.
