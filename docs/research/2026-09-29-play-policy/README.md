# Play 출시 준비: 설정에서 읽는 개인정보·라이선스 문서

## 문제와 요청

사용자가 Google Play의 앱 생성 화면에 있는 정책 준수·앱 서명·미국 수출법 선언을 보고 앱에 필요한 준비를 요청했다. 어린이도 대상이며, 공개 개발자 이름은 **TapeeTepee openstudio**, 문의 메일은 **wsndydtml@gmail.com**이라고 지정했다. 다른 회사처럼 별도 정책 페이지를 쓰면 되는지, 긴 글이 게임 미관을 해치지 않는지도 질문했다.

## 무엇을 왜 바꿨나

- Settings의 기존 스위치 아래에 `Privacy policy · Licenses` 작은 텍스트 링크를 추가했다. 평상시 게임/시작 화면에는 본문이나 동의 팝업을 추가하지 않았다.
- 선택한 문서는 앱 내 읽기 창에서 열리고, Close/Escape로 설정에 돌아간다. 앱에 HTML·서체·라이선스를 포함하므로 외부 웹사이트 이동이 필요하지 않다.
- 개인정보 문서에는 실제 저장 데이터, 운영자/문의 주소, 어린이 안내, 웹 호스팅/이메일/OS 백업과 개발자 게임 서버의 차이, 보관·삭제 내용을 영어/한국어로 작성했다. 현재 없는 광고·계정·결제 조항을 다른 회사에서 복사하지 않았다.
- 사용한 소프트웨어·서체의 실제 라이선스와 고지를 보존했다. 라이선스 자동 생성 도구는 게임 코드와 분리했다.
- 앱 고유 ID·업로드 키·저장 키를 유지하고 새 Android 산출물은 1.0.1 / code 2로 만들었다. 이전 AAB는 덮어쓰지 않았다.

앱 문서 작성이 법적 의무 전체 충족이나 스토어 심사 승인을 뜻하지 않는다. 개발자 선언·서명 설정·공개 URL 등록·대상 연령/데이터 보안 설문 등 남은 일은 [확인표](../../PLAY_POLICY_CHECKLIST.md)에 분리했다. 다른 게임 저장소는 수정하지 않았다.

## 결과와 이번 검증

- 자동 테스트 **217개 통과**, TypeScript/Vite 프로덕션 빌드 통과.
- 설정 스위치의 전후 좌표·크기가 동일하다.
- 개인정보/라이선스 열기·닫기, 한국어 앵커 이동, iframe 내부 Escape, 닫은 뒤 초점 복귀를 확인했다.
- 문서 열람 전후 localStorage 전체 값이 같으며, Settings → LIMITLESS 진입 후 테스트 진도 10과 9블록 판이 유지됐다.
- 320×568, 390×844, 768×1024에서 문서 가로 넘침이 없고 스크롤 후에도 Close가 화면에 남았다. 연구 캡처 자체는 모두 지정한 780×1688이다.
- 외부 HTTP를 차단하고 요청을 기록한 테스트에서 외부 요청은 0개였다. 두 문서는 앱 없이도 로컬 웹 서버에서 로그인 없는 HTML로 열린다.
- 새 AAB에 정책·라이선스·로컬 서체가 포함됐고, 배포 자산 45개와 실제 `dist/` 파일의 해시가 모두 일치했다. 서명·구조 검사도 통과했다. [AAB 검증](../../releases/2026-09-29-policy-aab/README.md).

재현 스크립트: [check.mjs](check.mjs). 다음 실행은 새 `CAPTURE_OUT` 경로를 지정해야 기존 이미지를 보존한다. Playwright 경로는 `PLAYWRIGHT_MODULE`, Chrome 경로는 `CHROME_PATH`로 지정할 수 있다. 스크립트와 연구 자료는 앱 번들에 포함되지 않는다.

## 첫 검사 실패와 보존

첫 검사에서는 문서를 닫고 바로 다른 문서를 열 때, 지연된 `close` 이벤트가 새 iframe 주소를 비워 문서 표시 대기 시간이 초과됐다. 이미 다시 열린 경우 이전 close 이벤트가 정리하지 않도록 수정한 뒤 전체 검사를 다시 통과했다. 첫 검사 캡처는 [attempt-1](attempt-1/)에 보존했으며 검증 완료된 전후 도판으로 쓰지 않는다. 첫 변경 후 설정 캡처에는 전환 애니메이션의 반투명 프레임도 포함돼 있다.
