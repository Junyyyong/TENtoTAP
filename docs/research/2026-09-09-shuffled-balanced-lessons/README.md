# 튜토리얼 숫자 위치 섞기와 색 배분 개선

## 문제 / 요청

사용자는 초반 정답 숫자가 항상 같은 위치에 나오는 점과, 독립 랜덤 색에서 갈색이 여러 칸에 몰려 붙는 점을 지적했다. 숫자 배치를 무작위화하고 색의 과도한 중복을 줄이도록 요청했다.

## 무엇을 왜 변경했는가

- 1–8단계 튜토리얼의 숫자 목록을 복제한 뒤 Fisher–Yates 방식으로 위치를 섞는다. 숫자 구성 및 정답 조합의 유일성은 유지하고, 새 판 생성 때 위치가 바뀔 수 있다. 무작위이므로 우연히 이전 배치가 다시 나올 가능성은 있다.
- 기존 아홉 색에서 사용 횟수가 가장 적은 색을 우선하고, 상하좌우 이웃과 같은 색은 제외한 뒤 후보에서 추첨한다. 2×2 및 3×3의 새 판은 중복 색이 없다. 큰 판은 색을 재사용하되 새 판의 같은 색 이웃을 피한다.
- 현재 화면의 배정 색은 선택·시계 갱신 때문에 바꾸지 않는다. 칸이 재충전되면 유지 중인 다른 칸을 고려해 색을 배정한다. 기존 칸을 강제로 다시 칠하지 않는다.
- 숫자용 게임 난수와 화면 색용 crypto 난수는 분리한다. 시간·점수·정답 규칙·보너스 영상은 유지한다.
- 직전 사용자 요청인 LIMITLESS의 원래 60 스톱워치 아이콘 복원도 이번 작업 화면에 포함된다. 실제 초반 제한 시간은 15초 그대로다.

## 결과와 검증

- 테스트 138개와 프로덕션 빌드 통과. 튜토리얼 각 30개 시드에서 숫자 목록 보존·의도한 정답 길이·다양한 위치를 확인했다. 기존 모든 부분집합 정답 유일성 검사도 유지한다.
- 2×2·3×3 각각 100개 시드에서 색 중복 없음, 2×2부터 9×9까지 각각 100개 시드에서 같은 색의 상하좌우 인접 없음 확인. 새 판 테스트이며 모든 동적 재배치 이력을 전수 검증한 것은 아니다.
- 모바일 브라우저에서 아홉 블록의 서로 다른 색, 시간·선택 후 색 유지, 수식 칸 색 일치를 검증했다. 실제 사용자의 미적 선호·학습 효과를 입증하는 자료는 아니다.
- [check.mjs](check.mjs)는 게임에서 import하지 않는 연구 스크립트다. 후속 캡처는 새 경로를 사용해 확정된 원본을 보존한다.
