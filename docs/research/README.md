## 기록 방식

TAPtoPICK 연구 폴더(참고 커밋 `0f56bf0b27f05fb233998ded079aa18d5fbeb69d`)의 날짜별 기록·스크린샷·재현 스크립트·검증 자료 구성을 참고했다. TAPtoPICK 파일은 변경하지 않았다.

앞으로 화면 또는 규칙이 바뀌면 별도 날짜-주제 폴더에 다음 내용을 추가한다.

1. 문제/요청, 변경 내용, 설계 이유와 근거의 출처.
2. 변경 전후 소스 커밋. 과거 화면을 재현하면 재현 촬영일과 원래 커밋 날짜를 구분한다.
3. 원본 PNG, 캡션, 촬영 조건, 검증 결과. 비교 화면은 같은 viewport와 DPR로 촬영한다.
4. 확인하지 않은 사항과 제한. 기대 효과를 실제 관찰 결과처럼 쓰지 않는다.

기존 기록·원본은 덮어쓰지 않고 새 폴더를 만든다. 논문에 실제 인용할 때는 저장소 커밋과 그림 파일 ID를 함께 기록한다. 아트워크의 출판 사용 권한은 이 개발 기록으로 입증되지 않는다.

## 인쇄용 원본

기본 규격은 390×844 CSS px, DPR 4의 **1560×3376 PNG**다. 원래 모바일 레이아웃을 브라우저에서 높은 픽셀 밀도로 렌더링하며, 작은 캡처를 확대하지 않는다. 300ppi 배치 기준 최대 약 **13.2×28.6cm**다. PNG에 DPI 메타데이터가 없어도 출판 도구에서 실제 배치 크기를 지정하면 된다. 300ppi는 이 자료의 작업 기준이며 출판사별 규격을 대신하지 않는다.

문자·SVG는 높은 해상도로 렌더링되지만 PNG/WebP 원본 자산의 디테일은 원본 품질에 제한된다. 스크린샷을 확대·JPEG 재압축하지 말고 이 폴더의 원본을 사용한다.

TAPtoPICK의 `docs/research` PNG 58장은 확인 시점 모두 **780×1688px**였다. 같은 300ppi 기준 가로 약 **6.6cm**에 해당한다. 작은 병렬 비교용은 가능하지만 10cm 이상 폭으로 사용할 이미지는 DPR 4 이상 원본 재촬영을 권한다. 해당 저장소의 `store` 및 과거 `docs/screenshots` 이미지 전체를 검사한 결과는 아니다.

## 다시 캡처하기

Node.js, 프로젝트 의존성, Playwright 및 Chrome이 필요하다. Playwright는 현재 작업 환경에 있으며 package.json의 고정 의존성은 아니므로 별도 환경에는 설치해야 한다.

```sh
npm run dev -- --host 127.0.0.1
# 별도 터미널: 새 경로로 기록하여 기존 원본 보존
CAPTURE_OUT=docs/research/YYYY-MM-DD-topic node docs/research/capture.mjs
```

`CAPTURE_URL`과 `CHROME_PATH`로 서버/브라우저 경로를 지정할 수 있다. [스크립트](capture.mjs)는 원본 이미지와 manifest를 생성하며, 게임의 실행 코드에서 불러오지 않는다. 향후 선택자·게임 구조가 바뀌면 스크립트도 갱신하고 해당 커밋을 기록한다.
