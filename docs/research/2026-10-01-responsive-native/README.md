# Android 밀도 보정 + 가용 화면 반응형 / 새 아이콘

## 요청과 문제

2026-10-01 사용자 요청: TAPtoTEST의 최신 방식을 읽기 참고해 Android의 고정 390×844 전체 축소를 없애고, 기기 종횡비에 반응하되 동일 기기의 화면 확대/축소 설정으로 배치가 바뀌지 않게 한다. 스튜디오는 기존 주황색 전체 바탕과 온전한 로고, 커버는 원본 한 장의 가로 100%·원래 비율·세로 중앙 정렬로 표시한다. 글자/서체/색/효과/규칙/저장/패키지/서명 키는 유지한다. 제공 아이콘을 적용하고 기존 스토어 7장에 대응하는 최신 이미지도 준비한다. 이번 작업은 소스와 검증만이며 AAB·push는 금지한다.

## 무엇을 왜 바꿨나

- `nativeFrame.ts`: TAPtoTEST처럼 `scale = min(가용 너비 / 390, 가용 높이 / 640)`로 밀도를 보정하고, 논리 너비·높이는 `가용 크기 / scale`로 계산한다. 390×844는 참고 치수이고 강제 종횡비가 아니다. 일반 세로 화면은 높이를 따라가고, 짧고 넓은 화면은 논리 너비가 늘어나 레이아웃을 다시 계산한다. 동일한 물리 창/안전영역에서 OS 밀도를 바꾸면 논리 치수와 물리 배치가 같아진다.
- 시스템 바/카메라 영역: 기존 MainActivity의 **WebView와 실제로 겹치는 나머지 영역** 보고를 유지한다. 명시적 0이 있으면 CSS/Capacitor 안전영역 값보다 우선해 이미 패딩된 영역을 두 번 제외하지 않는다. 일반 화면은 안전한 가용 창 안에 놓인다. 스튜디오/커버만 전체 WebView 창까지 색/이미지를 확장한다.
- 스튜디오: 기존 `#e95532` 유지, 로고 `object-fit: contain`·높이 제한으로 전체 글씨 보존. 커버: 기존 파일/비율 그대로, 가로 전체·세로 중앙·흰 바탕. 별도 그라데이션·반복·합성 이미지 없음.
- `nativeResponsive.css`: Android에서만 실제 너비/높이에 따라 여백·로고·버튼 패딩·보드 가용 공간을 조절한다. 태블릿의 HUD/Settings/START는 최대 560px의 중심 열에 놓아 콘텐츠에서 멀어지지 않게 한다. 메뉴의 21px/13px, Settings 링크 14px, 탐색 버튼 44px 등 기존 기준은 유지한다. 화면 크기 메뉴는 추가하지 않는다.
- `titleLayout.ts`: 메뉴 로고/버튼/음악 프롬프트가 겹치면 자연스러운 스크롤 흐름을 사용한다. Android에만 적용하고 기존 웹 배치는 그대로 둔다.
- `nativeCanvasScale`: 현재 논리 너비로 변환한다. 넓어진 태블릿에서 포인터/점수 팝업/완성 그림의 좌표가 틀어지지 않게 한다. 터치 좌표 자체는 클라이언트 좌표를 유지한다.
- `boardView.ts`: Android만 소수점이 유지되는 computed CSS 크기로 보드를 측정한다. 정수 `clientHeight`가 올림한 공간을 마지막 행에 잘못 주지 않는다. 기존 웹 측정 경로는 유지한다. 정사각형 블록, 색, 선택/취소, 규칙은 바꾸지 않는다.
- 아이콘: 새 원본은 2134×2135, SHA-256 `a2ffb3c0936d89cc020fd3014c6321e61c7c0bc0b7af1407aad8c8bfaf6201e0`. 1픽셀 내보내기 차이는 contain 여백으로 처리하며 원본을 잘라내거나 찌그러뜨리지 않는다. 5밀도 × 일반/원형/adaptive 전경 15개와 스토어 512×512를 생성했다. 주변 색은 원본 바탕 `#ea5836`, adaptive 내용 안전 영역은 기존 60dp/108dp 유지.

## 참고 소스와 보존

TAPtoTEST의 `src/ui/nativeFrame.ts`, `src/ui/pickLayout.ts`, `src/ui/styles/nativeResponsive.css`, `src/ui/styles/title.css`, `src/ui/styles/tokens.css`를 읽기 참고했다. 참조 파일 해시를 검사 시작/끝에 비교하며 다른 게임 저장소는 수정하지 않았다. 검사 도중 참고 저장소의 `nativeResponsive.css`가 외부에서 변경됨을 감지했다. 이후 바뀐 파일을 다시 읽었으며 밀도/가용 크기 계산과 커버 규칙은 같고 TEST 전용 HUD 너비 제한 일부가 제거된 차이다. TEN의 별도 HUD 중심 열은 이 게임의 반응형 배치 판단으로 유지한다. 마지막 검사 도중에는 TEST의 `tokens.css` 외부 변경도 감지해 시작/종료 해시 차이를 기록했다. 이를 TEN의 변경으로 해석하거나 뒤따라 수정하지 않았다. 마지막 검사 시작 시의 정확한 참고 소스를 `final-2/reference-source/`에 보존하고, 외부 변경 여부는 실패와 분리해 JSON에 기록한다.

`src/core`, `src/content`, `public` 전체와 저장소 어댑터/토큰/게임·설정·리액션 기본 CSS, HTML, Capacitor 설정, Android build.gradle/MainActivity를 이전 커밋과 해시 비교한다. 패키지 `io.github.junyyyong.makezero`, 기존 1.0.5/code7 및 서명 파일은 그대로다. 테스트·촬영 스크립트는 게임에 import하지 않는다.

## 실기기 한계와 다음 확인

macOS Chrome의 모의검사이며 Galaxy/Android System WebView의 실기기 검사와 다르다. `adb devices` 연결 기기 없음. 실제 OS 확대 설정·카메라 컷아웃·네이티브 패딩 상태·시스템 바 바깥 배경·기기별 기본 서체·영상 디코딩/음향은 AAB/설치 APK가 준비된 다음 실제 기기에서 확인해야 한다. OS 설정 자체를 변경하거나 접근성 돋보기 배율을 상쇄하지 않는다. 소스와 검증만 수행했으며 새 설치 파일 배포는 아직 없다.
