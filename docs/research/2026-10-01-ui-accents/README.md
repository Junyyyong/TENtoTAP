# 흰색·회색 기본 UI와 기존 강조색 복원

후속 요청의 [원형 회색 탐색 버튼·최신 전체 화면 비교](navigation-review/index.html)와 [추가 검증](navigation-review/README.md)을 별도로 보존했다. 아래 내용과 초기 캡처는 강조색 복원 시점의 기록이다.

## 요청과 문제

2026-10-01 사용자는 TAPtoTEST를 참고해 흰색/회색 바탕과 기본 박스는 유지하되, 강조되는 제목·아이콘·버튼·기록·게이지·스위치는 원래 색과 효과를 복원하도록 요청했다. 특히 메인 게임명은 파란색, Settings 링크는 원래 주황색으로 지정했다. 직전 중립 UI가 강조색까지 회색으로 바꿔 중요한 동작과 상태가 덜 구별되던 점을 수정했다.

[780×1688 PNG 전후 비교 갤러리](index.html) · [최종 상세 검증](final-viewport-verified/verification.json)

## 무엇을 왜 바꿨는가

TAPtoTEST의 `docs/research/2026-10-01-ui-accents/README.md`, `src/ui/styles/neutralUi.css`, `tokens.css`를 **읽기 참고만** 했다. TAPtoTEN의 기존 CSS를 직접 대조하고 같은 ‘기본 면과 강조 역할의 분리’를 적용했다. TEST의 게임 색이나 기능은 복사하지 않았다.

`tokens.css`에서 원래 의미별 강조색만 되살리고, 기본 면과 별도 강조용 그림자/기록 색을 분리했다. 화면별 CSS의 강조 요소만 원래 선언으로 복원했다. 글자 크기·굵기·서체·행간·버튼 크기·위치·간격, 고정 비율 프레임·안전영역·터치 좌표, 게임 규칙·저장·음악·이미지/영상은 변경하지 않았다. 게임 런타임의 TypeScript 파일도 이번 작업에서 변경하지 않았다.

## 검증과 한계

- `npm test`: **25개 파일 / 239개 테스트 통과**. 강조/중립 면 분리를 검사하는 회귀 테스트 3개 추가.
- `npm run build`: TypeScript 검사와 production build 성공. `git diff --check` 통과.
- **16개 화면, 전후 32장 PNG**: 메인, Settings off/on, 세 게임의 START/플레이, 일시정지, 긴급/벌점, 정오답 산식, 결과, 평가 점수/문구.
- 전후 **1,353개 요소**의 서체·크기·굵기·행간·간격과 좌표/크기를 대조했다. 좌표는 0.1 CSS px 미만 허용 오차. 기본 UI 박스 **76개**의 면색/그라데이션/그림자와 게임 블록/산식 요소 **820개**의 색/효과 보존을 확인했다.
- **35개 강조 선택자/상태 조합**의 색과 효과를 과거 커밋의 원래 계산값과 비교했다. 회색 기본 박스·일반 설명 글씨·로고 그림자 제거처럼 의도적으로 유지한 부분은 복원 대상에서 제외했다.
- Android 경로를 활성화한 Chrome **모의검사**: 390×844, 320×700, 480×1000 및 실행 중 viewport 변경, 상단 24/하단 48의 모의 남은 안전영역을 적용했다. 전체 기준 화면 390×844와 전후 동일 배치를 확인했다. 실제 Galaxy의 설정 변경/Android System WebView를 시험한 것은 아니다.
- 게임 규칙·진행·저장·TypeScript UI·프레임·안전영역·에셋 등 **107개 파일의 SHA-256 동일**을 확인했다. 그중 `public/` 에셋은 41개다. 과거 Git 메시지의 테스트 주장 대신 이번 실행 결과를 기록했다.
- `check-1`, `check-2`, `final`은 실패한 **검사 도구 시도**로 보존했다. 각각 SVG 클래스 객체의 엄격 비교, 아직 렌더되지 않은 기록 요소의 비교용 fixture 누락, 변환 좌표의 약 0.00003 CSS px 소수점 오차를 무오차로 비교한 것이 원인이다. fixture와 SVG 직렬화 및 0.1 CSS px 비교 기준을 수정한 `final-verified`는 색/배치 비교를 통과했으나, 정지된 검사 시계에서 resize 이벤트가 늦게 전달돼 320×700 행의 배율이 이전 크기로 남아 있었다. 이를 최종 크기 변경 검증으로 사용하지 않는다. 렌더링 후 명시적 resize 전달 및 **실제 배율과 크기별 예상 배율의 일치 검사**를 추가해 `final-viewport-verified`에 재검증 결과를 남겼다. 실패/중간 자료는 게임 결함이나 실기기 실험 실패를 뜻하지 않는다.

재현 명령: 외부 Playwright 경로를 `PLAYWRIGHT_MODULE`로 지정하고, **존재하지 않는 새 경로**를 `CAPTURE_OUT`으로 지정해 `node docs/research/2026-10-01-ui-accents/check.mjs`를 실행한다. 현재 의존성을 재사용하며, 새 기록을 기존 캡처 폴더에 덮어쓰지 않는다.

## 배포 범위

연구/캡처 스크립트와 자료는 게임에서 import하지 않으며 배포 실행 파일에 포함되지 않는다. TAPtoTEST 및 다른 게임 저장소는 수정하지 않았다. 이번 요청에서는 **AAB 생성·버전 변경·Git commit/push·Play 업로드를 하지 않았다.** 기존 AAB에는 이 변경과 보류 중인 고정 프레임 수정이 아직 포함되지 않는다. 실제 휴대폰 검증은 새 AAB를 별도로 요청해 설치한 뒤 필요하다.
