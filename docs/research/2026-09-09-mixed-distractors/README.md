# 정답 검사를 통한 방해 숫자 혼합 · 전환 확대축소 제거

## 문제와 요청

사용자가 스테이지 전환 때 판이 작아졌다 커지는 효과의 이유를 물었고, 9만 반복되는 방해 숫자를 각 판의 정답을 검사해서 섞도록 요청했다. 효과가 불필요하다는 설명과 함께 전환 확대축소를 제거하고 방해 숫자 생성 방식을 변경했다.

## 변경과 이유

- 6–29단계의 정답 숫자 조합은 유지한다. 빈 칸을 채울 때 1–9 각각을 후보로 넣고 **안내한 개수로 합계 10을 만드는 버튼 조합이 정확히 하나인지** 검사한다.
- 안전한 후보 중 덜 사용된 숫자를 우선한 뒤 무작위로 뽑는다. 7·8도 조건에 맞으면 사용하며 9만 채우지 않는다. 정답과 위치·방해 숫자는 게임 시드로 재현 가능하다.
- 짧은 개수의 합계 10은 기존 합의처럼 정답이 아니다. 예를 들어 세 블록 연습에서 두 블록 합계 10은 거절한다. 모든 개수의 합계 10이 하나라는 뜻이 아니다.
- 판 등장 시 350ms 확대축소/투명도 애니메이션을 제거했다. 500ms 전환 입력 잠금과 그 동안의 시계 정지는 유지해 다음 판을 연속 터치로 건드리지 않게 한다. 오답 흔들림, 반짝임, 영상, 실제 보드 크기 확장은 유지한다.
- 숫자별 연습 조합·30단계 전체 비우기·영상 일정·제한 시간·저장 진도·블록 색 정책은 변경하지 않았다.

## 전후 화면 / 조건

Chrome / 390×844 CSS px / DPR 2 / **780×1688 PNG**. 양쪽 신규 프로필·같은 고정 시계와 게임 난수 초기값. 색상 crypto 난수는 고정하지 않는다. 이전 6·14·23·30은 저장 진도 주입 조건이며, 이후는 1부터 실제 터치로 도달해 점수와 경과 시간은 다를 수 있다. 유한 애니메이션 완료 후 촬영하므로 전환 움직임 제거는 정지 PNG가 아니라 브라우저 스타일 검사로 확인했다.

## 검증과 한계

- 테스트 140개 및 프로덕션 빌드 통과. 1–29단계 각각 50개 시드의 모든 부분집합을 검사해 요구 개수의 정답이 하나임을 확인했다. 6–29단계는 방해 숫자가 최소 두 종류인지도 확인했다.
- 모바일 Chrome에서 1→31 실제 터치 진행, 첫 두 판의 안내, 5·13·22·30 영상과 시계 정지, 각 정답 직후 판 transform이 none인지 확인했다. 브라우저 예외 없음.
- 생성 알고리즘은 후보 추가 때마다 정답 수를 검사한다. 테스트한 시드가 모든 난수를 전수 검증한다는 뜻은 아니다. 사용자 실험·학습 효과·실기기 Safari 품질은 이번 검증 범위가 아니다.
- [check.mjs](check.mjs)는 연구용이며 게임에 import하지 않는다. 확정 원본 보존을 위해 후속 캡처는 새 폴더에 저장한다.
